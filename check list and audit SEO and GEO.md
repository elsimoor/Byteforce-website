Here's the checklist from a client's point of view, in roughly the order they decide whether to trust you.

**1. Hero section (first 5 seconds)**
- [x] A clear headline saying who you help and what you do (e.g. "We build and maintain SaaS products and websites")
- [x] A one-line subheadline with the outcome the client gets (faster launch, fewer bugs, no downtime)
- [x] One primary call to action above the fold ("Book a free call" or "Get a quote")
- [x] A visual that shows real work, not generic stock images

**2. Services**
- [x] Separate, clearly named offers: SaaS/MVP development, bug fixing and audits, website maintenance
- [x] Short descriptions of what's included in each, in plain language
- [x] The tech stack you work with (React, Next.js, Node, Laravel, etc.)
- [x] Who each service is for (startup founder, business owner with an existing site)

**3. Proof of competence**
- [x] 3 to 6 case studies with problem, solution and result, ideally with numbers (load time cut by 60%, 40 bugs fixed in a week)
- [x] Live links or screenshots of real projects
- [ ] Testimonials with a real name, photo, company and role
- [ ] Client logos, if you have them
- [ ] Reviews on external platforms (Google, Clutch, Upwork) as independent proof

Case studies on the homepage are Coco Inbox, Proche de moi, Dealkhir and Tourispeak. Each has a screenshot of the live site, a case-study page, and a result stated as where and when it went online. No performance percentage was added, because none is on file.

Testimonials, client logo files, and review quotes are still open. A Google listing link is on the page. A testimonial needs a real name, role, company and photo from a client. Logos need files you actually have.

**4. Process**
- [x] A simple step-by-step flow: discovery → proposal → build/fix → testing → launch → support
- [x] How you communicate (Slack, WhatsApp, weekly updates, a project board)
- [x] How you handle bugs found after delivery
- [x] Who owns the code and the accounts at the end (clients worry about this a lot)

**5. Maintenance and support (a big concern for site owners)**
- [x] Plans or packages: monitoring, backups, security updates, uptime checks, content edits
- [x] Response times or SLA (e.g. "critical issues answered within 4 hours")
- [x] Whether there's a monthly retainer or pay-as-you-go option
- [x] An emergency or "my site is down" contact path

**6. Pricing and expectations**
- [ ] Starting prices, ranges or package tiers (even "from $X" filters out mismatched leads)
- [x] What affects the price
- [x] Typical timelines (MVP in 4 to 8 weeks, bug audit in 3 days)
- [x] A free consultation or audit offer to lower the barrier

Starting prices stay off the page until you set a real figure. The page says what moves the price, that an audit is usually a few days, that a first version is usually several weeks, and that the first 30-minute call is free.

**7. Trust and credibility**
- [ ] An About section with real team photos, names and experience
- [ ] Years in business, number of projects delivered
- [x] Business details: location, registered company name, a real address or city
- [x] NDA and confidentiality assurance
- [x] Security practices (code reviews, staging environments, backups)

The about block shows the Casablanca office and the count of published projects, and links to `/a-propos`. A team photo, a person's name, and a founding year are not on file, so those two lines stay open.

**8. Contact and conversion**
- [x] A short contact form (name, email, project type, budget range, message)
- [ ] Multiple contact options: email, WhatsApp, calendar booking link (Calendly or Cal.com)
- [x] A CTA repeated after each major section, not only at the bottom
- [x] A promise on reply time ("We reply within 24h")
- [ ] A professional business email, not only a Gmail address

**9. FAQ**
- [x] What if I already have code written by someone else?
- [x] Can you work with my existing stack?
- [x] Do you offer ongoing support after launch?
- [x] How do payments work (deposit, milestones)?
- [x] What happens if the scope changes?

**10. Technical quality of the page itself**

Clients judge a dev agency by its own website:
- [ ] Loads fast (aim for under 3 seconds, good Lighthouse score)
- [ ] Fully responsive on mobile
- [ ] No broken links, images or console errors
- [x] HTTPS and a clean, consistent design
- [ ] Accessible contrast and readable fonts
- [x] Basic SEO: title, meta description, Open Graph preview, sitemap
- [x] Privacy policy and terms linked in the footer

**11. Red flags that make clients leave**
- Vague claims like "we do everything" with no specifics
- No portfolio or only mockups
- No pricing or process information at all
- Dead links, placeholder text or a slow, broken site
- No visible human behind the agency
